# 06 · 真实数据接入指南

这份文档面向**不需要懂数据处理**的使用者。目标：读完能独立把真实数据灌进系统，
出问题知道怎么查。

---

## 1. 最短路径

打开终端，进到项目根目录（就是有 `fetch_real_data.py` 的那个目录），执行：

```bash
python fetch_real_data.py
```

然后等。首次运行会下载约 20 MB 的数据集，解析约 200 万行原始记录，
整个过程通常 1–3 分钟（取决于网速）。

看到最后一行 `完成。下一步：` 就说明成功了。接着：

```bash
python -m homeshift status
```

如果 `数据来源` 那行显示 `真实数据集 uci`，就都对了。

---

## 2. 这条命令到底做了什么

脚本会打印 8 个步骤，每一步的含义：

| 步骤 | 做什么 | 为什么需要 |
| --- | --- | --- |
| 1/8 数据集 | 确认用哪个数据集、什么许可 | 答辩要能说清数据来源与合规性 |
| 2/8 下载 | 多镜像下载 + 断点续传 | 一个链接挂了自动换下一个；中断了下次接着下 |
| 3/8 解析 | 1 分钟粒度 → 半小时，缺失值如实统计 | 项目所有算法都按半小时设计 |
| 4/8 挑窗口 | 选一段最近的、完整度最高的连续数据 | 数据集有 4 年，全塞给 LLM 又慢又贵 |
| 5/8 天气 | 拉取**同地点同时段**的真实气温 | 没有匹配的气温，天气归一化就是假的 |
| 6/8 写文件 | 写入 `data/usage.csv` 等 | 下游算法直接读这些文件 |
| 7/8 画像 | 从用电曲线反推作息 | 公开数据集不会告诉你"这家人几点睡" |
| 8/8 出处 | 写 `provenance.json`，同步配置 | 数据换国家了，币种/电价/碳因子要跟着换 |

## 3. 生成了哪些文件

```
data/
├── raw/                        原始下载文件（可删，删了会重新下载）
│   ├── uci_household_power.zip
│   └── household_power_consumption.txt
├── usage.csv                   半小时总表        timestamp,kwh
├── weather.csv                 半小时气温        timestamp,temp_c
├── usage_groundtruth.csv       分电器真值（仅部分数据集有）
├── profile.json                家庭画像（含"哪些是观测、哪些是假设"）
└── provenance.json             数据出处与质量报告  ← 答辩可直接引用
```

`provenance.json` 是最值得看的一个，它记录了：

- 数据集标题、许可、引用格式、原始下载链接
- 窗口区间与完整度百分比
- 原始行数、缺失率、丢弃了多少不完整时段
- 天气数据来源与覆盖情况
- **已知局限**（`known_limitations`）—— 系统主动承认自己的不足

## 4. 换数据集

```bash
python fetch_real_data.py --list
```

### 4.1 用你自己家的电表数据（最贴近产品场景）

新加坡 SP Group 用户：
1. 打开 SP Utilities App
2. Usage → Electricity → 选择时间范围 → Download / Email CSV
3. 把 CSV 放到 `data/raw/` 下
4. 执行：

```bash
python fetch_real_data.py --dataset spgroup --file data/raw/你的文件.csv
```

系统会自动识别时间列和用电列。识别不出来时会把所有列名打出来，
你再手工指定：

```bash
python fetch_real_data.py --dataset spgroup --file data/raw/x.csv \
    --time-col "Reading Date" --value-col "Consumption (kWh)"
```

### 4.2 用任意 CSV（Ausgrid、Low Carbon London、老师给的数据）

```bash
python fetch_real_data.py --dataset csv --file 路径.csv \
    --time-col 时间列名 --value-col 用电列名 --value-unit kwh
```

`--value-unit` 很重要，填错会让数字差一倍：

| 值 | 含义 | 什么时候用 |
| --- | --- | --- |
| `kwh` | 该时段消耗的电量（默认） | 电表导出通常是这个 |
| `wh` | 瓦时 | 数值特别大（几百上千）时 |
| `kw` | 该时刻的平均功率 | 列名叫 power / demand / load 时 |
| `w` | 瓦 | 同上，但数值是几百上千 |

系统会自动推断原始采样间隔（用相邻时间差的众数），再按间隔把功率换算成能量。

### 4.3 常用可选参数

```bash
--days 90                 # 演示窗口天数（默认 63）
--weather openmeteo       # 全球通用，免密钥（默认）
--weather datagovsg       # 新加坡实测观测站（只覆盖近期日期）
--weather none            # 不拉天气（天气归一化会失效）
--keep-config             # 不要自动改写 config.json（保留你的电价设置）
```

## 5. 数据质量：系统怎么处理"脏数据"

真实数据一定有缺失。这里的处理原则是 **宁可丢弃，绝不编造**：

| 情况 | 处理方式 | 为什么 |
| --- | --- | --- |
| 某一分钟记录缺失（`?`） | 跳过该行，计入缺失统计 | 补 0 会凭空制造"节省" |
| 某半小时的样本 < 20 个（应有 30） | **整个时段丢弃** | 部分样本会低估该时段用电 |
| 整段数据缺失过多 | 挑窗口时自动避开 | 优先选完整度 ≥ 90% 的窗口 |
| 气温数据覆盖 < 50% | **不做天气归一化**，并明确告知 | 假的归一化比不归一化更危险 |

最后一条尤其重要。如果基线期没有气温数据、执行期有，朴素实现会得出
"CDH 从 0 涨到 275"这种荒谬结论，进而把节能效果算错。系统会检测到这种情况
并在复盘报告里写：**"天气归一化未生效 —— 覆盖不足，下面的数字包含气温影响，
请谨慎解读"**。

## 6. 验证负载分解到底准不准

这是选 UCI 数据集的核心理由 —— 它自带 3 路分表真值：

```bash
python -m homeshift eval-disagg
```

输出每个类别的**真值 / 估算 / 平均绝对误差（MAE）**。

映射关系写在 `provenance.json` 的 `category_map` 里，不是硬编码在代码中：

| UCI 分表 | 实际内容 | 映射到 | 已知污染 |
| --- | --- | --- | --- |
| sub_metering_1 | 厨房（洗碗机/烤箱/微波炉） | other | — |
| sub_metering_2 | 洗衣房（洗衣机/烘干机/**冰箱**/照明） | laundry | 冰箱混在里面，所以 fridge 没有独立真值 |
| sub_metering_3 | 电热水器 + 空调 | water_heater | 法国家庭空调极少，绝大部分是热水器 |
| unmetered | 总量减三路分表 | other | — |

**答辩时怎么说这件事**：不要假装映射是完美的。正确的说法是
"我们显式记录了每一处口径不匹配，误差里有多少来自算法、有多少来自数据口径，
是可以区分的"。这比声称 95% 准确率可信得多。

## 7. 一个重要的诚实声明

UCI 数据来自**法国温带地区**，而本项目的负载分解启发式最初是按
**新加坡热带气候（全年制冷、夜间开空调）** 设计的。在温带数据上，
`aircon` 这个类别实际混合了取暖、夜间热水与其他负载，
**不应简单理解为"空调"**。

系统对此做了两件事：

1. `provenance.json` 的 `known_limitations` 会自动写入这条声明
2. 诊断报告里该类别的措辞会随气候变化（温带下不会说"三台空调整晚运行"）
3. 配置项 `disaggregation` 的作息锚点与 `cdh_base_c` 会跟着数据集切换

这本身就是一个**很好的答辩素材**：它说明领域假设（domain assumption）
在 Agentic 系统里是一等公民，换了场景必须显式重新审视，
而不是让算法悄悄给出错误答案。

## 8. 故障排查

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `所有镜像都下载失败` | 网络需要代理 / 学校网络限制 | 设置 `HTTPS_PROXY` 后重试；或手工下载放到 `data/raw/` |
| 下载到一半中断 | 网络抖动 | 直接重新运行，会自动续传 |
| `不是有效的 zip 文件` | 下到了错误页面 | 删掉 `data/raw/*.zip` 重新运行 |
| `无法自动识别时间列/用电列` | CSV 列名不常见 | 按提示用 `--time-col` / `--value-col` 手工指定 |
| `Open-Meteo 没有返回数据` | 日期范围超出覆盖 / 坐标写错 | 用 `--weather none` 先跑通，再单独排查 |
| 数字看起来大了一倍 | `--value-unit` 填错 | 功率列要填 `kw` 或 `w`，不是 `kwh` |
| 换数据集后计划/记忆还是旧的 | — | 流水线会自动清空 `plans.json` / `memory.json` / `reviews.json` |

设置代理：

```bash
# macOS / Linux
export HTTPS_PROXY=http://127.0.0.1:7890

# Windows PowerShell
$env:HTTPS_PROXY="http://127.0.0.1:7890"
```

## 9. 想加一个新数据集？

只需两步：

1. 在 `homeshift/realdata/sources.py` 的 `DATASETS` 里加一项
   （下载链接、地区、电价、碳因子、分表映射）
2. 如果格式特殊，在 `homeshift/realdata/loaders.py` 里加一个解析函数，
   返回统一结构 `{"usage": [...], "truth": [...], "stats": {...}}`

上层的分解、模拟、追踪、导出**完全不用改**。
